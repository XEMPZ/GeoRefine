## 1. 新增功能（2 个页面）

### 1.1 OSGB 模型转换（导航第 7 项）

对倾斜摄影 OSGB 模型**逐顶点**做坐标/高程转换，输出仍是可在原引擎加载的标准 OSGB。

**核心实现**：`app/osgb/`（约 2000 行）

| 文件 | 作用 |
|---|---|
| `transform.py` | 顶点变换语义；仿射线性化（`affine_gain_absolute`）；轴序换算 |
| `flash.py` | 参数 → 仿射系数 → 调用 C++ 工具（`coeffs_for_document`） |
| `srs.py` | 解析 `metadata.xml`（SRS / SRSOrigin） |
| `osgb_job.py` | 瓦片发现、输出目录规划 |
| `osgb_io.py` + 4 个 `_wsl_*.py` | 文本层路径（`.osgt`）——**对照用，见 §5** |
| `cpp/osgb_vertex_transform.cpp` | **C++ 核心工具**（212 行，只做矩阵乘顶点） |
| `cpp/native/osgb_vertex_transform.exe` | Windows 原生成品（26 MB，全静态） |

**关键语义**（改动前不存在，需知悉）：

- **SRSOrigin 不变**：顶点承载世界坐标位移，局部坐标系不动。
- **轴序自动换算**：OSGB 顶点是 `(东,北,高)`，本项目约定 `(北,东)`，两者相反，
  读写处统一走 `transform2d.to_survey_xy`。
- **平面/高程独立勾选**：未勾选的部分逐位透传。
- **参数作用在绝对坐标上**：OSGB 顶点是相对 SRSOrigin 的局部偏移，
  故先加回原点、变换后再减回（见 `transform.py` 的 `apply()`）。

### 1.2 点云模型转换（导航第 8 项）

对 LAS/LAZ 逐点转换 X/Y/Z。**只动坐标**是硬约束。

**核心实现**：`app/pointcloud/`（约 700 行）

| 文件 | 作用 |
|---|---|
| `las_io.py` | LAS 读写封装（基于公开库 **laspy**）；分块读 / `write_like` |
| `las_transform.py` | 坐标变换（整块矩阵化，2.1e7 点/秒） |
| `las_job.py` | 批量作业；跳过索引文件；单文件容错 |
| `las_worker.py` | GUI 后台线程 |

**关键语义**：

- **只改 X/Y/Z**：强度、回波、分类、GPS 时间、RGB、自定义维度**逐位保留**。
- **scale/offset 不变**：它们是量化步长，改它等于改精度口径，不属于坐标转换。
- **轴序**：LAS 的 `X=东、Y=北`，同样需要换算。
- **点格式无关**：支持 0~10；无 RGB 的格式（0/1/4/6/9）不会凭空造出颜色字段。

## 2. 引擎改动（**最重要，请重点检查**）

只改了 **1 个引擎文件**：`app/common/params.py`（+95 −8 行）。

### 2.1 新增 `_grid_probe_xy`（绝对坐标探针）

```python
# __init__ 里：
self._grid_probe_xy = None   # None 表示输入本身即绝对坐标
```

**为什么需要**：大地水准面格网覆盖全测区，而 OSGB 顶点是局部偏移。
查 ξ 必须用"局部 + SRSOrigin"的绝对投影坐标反算经纬度，否则查不到格网点。

### 2.2 新增 `apply_planar_at(x, y, h, gx, gy, ...)`

```python
def apply_planar_at(self, x, y, h, gx, gy, do_plane=True, do_height=True):
    saved = self._grid_probe_xy
    self._grid_probe_xy = (float(gx), float(gy))
    try:
        return self.apply_planar(x, y, h, do_plane=do_plane, do_height=do_height)
    finally:
        self._grid_probe_xy = saved
```

平面部分仍按传入的 `(x, y)` 算，只有 ξ 查算用 `(gx, gy)`。**默认行为完全不变**
（不传探针时等价于原 `apply_planar`），因此对既有功能零影响。

### 2.3 `apply_planar` 支持"平面输入 + 格网"

**改动前**：平面坐标输入 + 参数含格网 → 直接报错拒绝。
**改动后**：按参数自带的 `projection_src` 反算源侧经纬度再查 ξ；
缺 `projection_src.l0` 时仍明确报错（绝不静默算错）。

### 2.4 新增 `_planar_to_src_bl(x, y, h)` —— 薄壳

反算逻辑**统一收敛到既有的 `_poly_src_point`**（不再有第二份实现）。
本方法只负责"缺投影时返回 `(None, None)` 而不抛错"。

### 2.5 `_poly_src_point` 增加可选参数 `psrc`

```python
def _poly_src_point(self, v1, v2, h, src_is_lonlat, psrc=None):
    ...
    psrc = psrc if psrc is not None else (self.param.get("projection_src") or {})
```

默认行为不变，仅允许调用方覆盖源侧投影（界面手填的带号/L0）。

### 2.6 报错文案不再硬编码 "gtx"

```python
# 改前： "请把该 gtx 放入 models/ 目录..."
# 改后： "请把该格网文件放入 models/ 目录（支持 gtx / tif / csv / zgf / ggf / grd / bin）..."
```

### 2.7 其它两个文件的小改动

| 文件 | 改动 |
|---|---|
| `app/__init__.py` | 新增 `app_root()`：打包后返回 exe 所在目录，否则项目根 |
| `app/gui/pages.py` | `_ROOT` 改用 `app_root()`；新增 2 个页面类；`_find_binary` 多处查找 |

## 4. 如何回退

**整体回退到 v1.0**（会丢掉全部新功能）：

```bash
git checkout 471ac92 -- app/common/params.py app/gui/pages.py app/__init__.py main.py requirements.txt
git checkout 471ac92 -- app/gui/main_window.py
# 新功能目录不在 v1.0 里，删掉即可（它们不被旧代码引用）：
rm -rf app/osgb app/pointcloud
```

**只回退引擎改动**（保留新功能，但新功能会失效）：

```bash
git checkout 471ac92 -- app/common/params.py
```

⚠ 注意：`params.py` 的改动是**向后兼容**的（新增方法 + 可选参数 + 一处文案），
既有功能不受影响。**回退它只会让 OSGB/点云的"平面源 + 格网"组合失效**，
没有别的收益。建议保留。

诚实记录，避免你盲信本说明：

| 我说过 | 实际 | 已修正 |
