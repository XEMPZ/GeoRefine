# app/pointcloud —— 点云模型转换（LAS）

## 契约

1. **只改顶点坐标（X/Y/Z）**，其余属性一律原样保留：强度、回波号、回波数、
   扫描方向、分类、合成/关键点/保留标志、扫描角、user_data、点源 ID、
   **GPS 时间、RGB**。测试 test_las_transform_only_coords 逐维度断言"逐位不变"。
2. **头部元数据原样保留**：点格式、版本、**scale/offset**、VLR（含 CRS WKT）、
   system_identifier、generating_software。只按实际写出值重算 min/max。
3. **LAS 读写用公开库 laspy**（不自研格式解析）。缺失时明确提示 pip install laspy，
   不静默降级。
4. **坐标换算委托项目既有模块**（app.common.params.ParamApplier / apply_lonlat），
   本模块不含任何坐标公式。

## 为什么不动 scale/offset

LAS 的坐标存成 原始整数 × scale + offset，**scale 就是量化步长**
（实测数据 0.0001 m）。改写 scale/offset 等于改变精度口径，不属于坐标转换，
因此一律沿用源文件的值。坐标按原 scale 重新量化，往返误差上界为半个量化步长
（实测 5.0e-05 m，正好是 scale=1e-4 的一半）。

## 轴序（与 OSGB 同一个坑）

| 数据 | 平面分量顺序 | 依据 |
|---|---|---|
| **LAS** | **X=东(E)、Y=北(N)** | LAS 头的 CRS 声明 AXIS[Easting,EAST], AXIS[Northing,NORTH]；实测 X 5.27e5（东坐标量级）、Y 3.56e6（北坐标量级） |
| 本项目测量约定 | x=北(N)、y=东(E) | ARCHITECTURE.md:11 |

换轴复用 app.core.transform2d.to_survey_xy。

⚠ **实现要点（踩过的坑）**：affine_gain_absolute 得到的 gain 直接工作在
**LAS 原序 (东,北,高)** 上 —— 因为 PlanarVertexTransform 内部换轴、
affine_coefficients 又换回，净效果是 gain 直接作用于 LAS 的 (X,Y,Z)。
因此 na = column_stack([xe, yn, zz])，**不要预换轴**。
四个候选列序的实测对照：

| 候选 | 最大偏差 |
|---|---|
| na=(N,E,H) 取列(0,1) | 3.038e+06 m |
| **na=(E,N,H) 取列(0,1)** | **9.313e-10 m** ✅ |
| na=(N,E,H) 取列(1,0) | 8.593e+01 m |
| na=(E,N,H) 取列(1,0) | 3.038e+06 m |

## 性能：整块矩阵化

逐点 Python 调用引擎约 **8.6 万点/s**，4913 万点的单个 LAS 要 **9.5 分钟**，不可接受。
参数变换是仿射的，因此整块矩阵化：

| 方式 | 吞吐 | 4913 万点 |
|---|---|---|
| 逐点调用引擎 | 8.6e4 点/s | 9.5 分钟 |
| **整块矩阵化** | **2.1e7 点/s** | **2.4 秒**（快 240 倍） |

线性化点取**本块坐标均值**（不是固定的 0 邻域）—— LAS 坐标是绝对值，
在 3.5e6 量级上做固定的 0 邻域线性化会算错旋转/尺度。

真实全文件实测（4913 万点 / 1.56 GB，含读写）：**6.9 秒**，7.1e6 点/s。

## 与逐点引擎的一致性

在 LAS 自身位置造自洽四参数（含旋转尺度）后逐点对照：

    与真值(四参数直接应用): 东 6.2e-06  北 8.7e-06  高 0.0 m
    与逐点引擎            : 1.397e-09 m

## 颜色与强度：性质完全不同，别混为一谈

按 LAS 官方点记录布局（laspy 枚举核实）：

| 点格式 | 字节/点 | **强度** | **RGB** | GPS 时间 |
|---|---|---|---|---|
| 0 | 20 | 有 | **无** | 无 |
| 1 | 28 | 有 | **无** | 有 |
| 2 | 26 | 有 | 有 | 无 |
| 3 | 34 | 有 | 有 | 有 |
| 4 | 57 | 有 | **无** | 有 |
| 5 | 63 | 有 | 有 | 有 |
| 6 | 30 | 有 | **无** | 有 |
| 7 / 8 | 36 / 38 | 有 | 有 | 有 |
| 9 | 59 | 有 | **无** | 有 |
| 10 | 67 | 有 | 有 | 有 |

**结论**：

* **强度是 LAS 的必备字段** —— 所有点格式都含 intensity，没有"不包含强度"的 LAS。
  但"字段存在"≠"有内容"：扫描仪不做回波强度测量时，64 个点全是 0。
* **颜色是可选的** —— 点格式 2/3/5/7/8/10 才有 RGB 字段；
  0/1/4/6/9 **连这个字段都不存在**（点记录里没有那 6 个字节），
  不是"用 0 占位"，而是**根本没有**。
* **有字段但无颜色时**，导出软件会填占位值。实测两种填法：
  * 隧道扫描仪：**65535,65535,65535（全白）**
  * 有些设备填 **0,0,0（全黑）**
* 强度也同理：字段必在，值可能全 0（实测隧道数据即如此）。

**因此"无颜色"有三种形态，实现必须都正确处理**：

| 形态 | 表现 | 处理 |
|---|---|---|
| 真彩色 | RGB 各不相同 | 逐位保留 |
| 占位色 | 全白 / 全黑 | 逐位保留（**不许做归一化或颜色压缩**） |
| 无该字段 | 点格式 0/1/4/6/9 | 输出也**不得凭空造出** RGB 字段 |

实测（点格式 0/1/2/3 各造一份转换）：

    ```
    格式 0 (20 字节/点): 转换 OK | 维度 15->15 一致 | 有RGB False | 非坐标不一致 无
    格式 1 (28 字节/点): 转换 OK | 维度 16->16 一致 | 有RGB False | 非坐标不一致 无
    格式 2 (26 字节/点): 转换 OK | 维度 18->18 一致 | 有RGB True  | 非坐标不一致 无
    格式 3 (34 字节/点): 转换 OK | 维度 19->19 一致 | 有RGB True  | 非坐标不一致 无
    ```

## 兼容性：实测过的两类真实数据

### A. 无人机/背包激光雷达（M300+AA9 scanner）

| 属性 | 值 |
|---|---|
| 点格式 / 版本 | 3 / 1.2 |
| 量化步长 | 0.0001 m（0.1 mm） |
| offset | (526777, 3564283, 994) |
| CRS | WKT2，含 central_meridian=105 |
| 规模 | 4913 万点 / 1.56 GB（12 文件 / 17.4 GB） |

### B. 隧道三维激光扫描仪（智隧慧眼）

| 属性 | 值 |
|---|---|
| 点格式 / 版本 | 3（多数）与 2 / 1.3 |
| 量化步长 | **0.01 m（1 cm，粗 100 倍）** |
| offset | **(0, 0, 0)** |
| **RGB** | **65535,65535,65535 全白占位——"没有颜色"** |
| 强度 / 分类 | 全 0 |
| CRS | **无**（VLR = 0） |
| system_id | java LAS Exporter |
| 规模 | 55 文件 / 9322 万点 / 10.5 s |

隧道数据实测结果：坐标偏差 东 5.0e-03 / 北 3.7e-03 m（**恰在量化极限
scale/2 = 0.005 m 之内**）；非坐标维度（含白色占位 RGB、全零强度、全零分类）
全部逐位保留；scale/offset/点格式/版本/VLR 全部不变。

### ⚠ 两个必须知道的数据陷阱

**1. 自定义额外维度 → 不能照 point_format.id 新建头**
扫描仪的"合并"导出会带自定义维度（如 `Original cloud index`），
此时 `header.point_format.id` 报的值与实际块不符，按 id 新建头会报
`LaspyException: Incompatible point formats`。
**正解：直接沿用源头的头对象**（`deepcopy(src_header)` 并把 `point_count` 归零
让 laspy 自行统计），这样自定义维度、VLR/CRS、scale/offset 全部原样保留。

**2. 文件被占用 → 批处理必须逐文件容错**
扫描仪软件常驻时会锁住正在写的 LAS（`Permission denied` / WinError 32）。
`convert_pointcloud` 对每个文件单独 try，失败登记为该文件失败并继续，
**不中断整批**。实测：首次运行时 15 个 `tx_*.las` 被占用，其余 53 个正常转换完成。
